# Vertux Workspace

Рабочее место студии: лиды, план контактов, журнал звонков, демо, учёт сделок,
импорт CSV/XLSX и тренер менеджера. Вход и системные разделы обслуживает Nexus.
Статический интерфейс без сборки; данные проектов хранятся в Supabase.

Кнопка «Набрать» передаёт номер телефонному приложению через `tel:`. Соединение,
длительность и запись разговора Workspace не получает. Сохранение итога звонка — ручное.
Rockefeller передаёт готовый файл; автоматический браузерный мост не реализован.

ИИ работает через отдельную защищённую службу тренера с сессией продукта. Четыре режима
проверены реальными ответами на синтетических диалогах. Общий бюджет запуска —
$5 без автоматического пополнения; расход и неопределённые резервы переживают рестарт.
Старый `n8n/vertux-ai-trainer.json` — неактивный архив.

## Изолированный просмотр

```powershell
node tests/preview-server.mjs
```

Открыть `http://127.0.0.1:47861/`. Все компании вымышлены, ответы ИИ имитируются,
данные живут только в памяти вкладки и сбрасываются при обновлении. Ссылка с
`?manager` показывает роль менеджера, с `?viewer` — наблюдателя.
Стенд отдаёт только разрешённые публичные файлы; исходники сервера и документы
через него недоступны. Для системных разделов нужны локальные ассеты Nexus 1.2.3
из соседнего проекта. Если там другая версия, до запуска задайте
`WORKSPACE_SERVICE_ASSETS` на каталог проверенной v1.2.3 в актуальном checkout Nexus.

Обычная раздача `index.html` использует рабочую конфигурацию Supabase/Nexus.
Для проверок записи использовать именно изолированный стенд.

## Проверки

```powershell
node --test tests/workspace-rules.test.cjs tests/data-concurrency.test.cjs tests/trainer-server.test.mjs tests/trainer-entrypoint.test.mjs tests/import-safety.test.cjs tests/nexus-contract.test.cjs
node tests/inspect-ui.cjs
node tests/verify-ui.cjs
```

UI-проверкам нужен запущенный стенд, Chrome и уже установленный Playwright.
`WORKSPACE_PLAYWRIGHT` может указать каталог модуля; по умолчанию используется
существующая установка в соседнем `projects/vertux-invest-workspace`.
Отчёты и снимки лежат в `evidence/sales-audit/` и содержат только тестовые данные.

Деньги хранятся отдельно в `workspace_project_finance` и доступны только owner/admin
через RLS. Права читаются из текущей серверной записи пользователя и ограничены
продуктом/организацией. Миграция, матрица ролей и откат проверяются на отдельной
восстановленной базе. Подробный внутренний аудит и live receipts не публикуются
в этом открытом репозитории.
